## 1. O que já existia e o que faltava

A coluna `funcionarios.status`, com os valores `ativo` e `inativo`, **já existia** desde a correção 04. Duas regras já a usavam:

- funcionário inativo **não recebe EPI**, porque o banco recusa (correção 14);
- as telas de entrega só listam funcionários ativos.

**O que faltava:**

1. Não havia **nenhum botão** para inativar. Só dava para mudar pelo SQL Editor.
2. A lista mostrava todo mundo, inclusive os inativos.
3. Não havia lugar para guardar **quando** e **por que** a pessoa saiu.

**Por que inativar e não apagar?** O funcionário tem histórico de entregas, e a ficha de EPI dele precisa ficar guardada. A correção 10 já impede apagar quem tem histórico.

## 2. Como funciona agora

### Lista de funcionários

- Funcionário **inativo some da lista e da busca**.
- Ao lado do filtro de obra apareceu a caixinha **"Mostrar inativos (n)"**, onde n é quantos inativos existem. Marcando, eles voltam a aparecer, com fundo cinza e a data ("desde 31/10/2026").
- Se a busca não acha ninguém entre os ativos, a tela sugere marcar "Mostrar inativos".
- **Bônus:** a busca agora ignora acentos e maiúsculas. Digitar "joao" encontra "João".

### Ficha do funcionário → "Situação do funcionário"

O bloco aparece só para quem pode alterar o cadastro, que hoje é o Administrador.

**Se o funcionário está ativo:** o botão **"Inativar (desligamento)"** abre um formulário com:

- **Data do desligamento:** já vem com a data de hoje. Não aceita data futura nem anterior à admissão.
- **Motivo:** demissão sem justa causa, demissão por justa causa, pedido de demissão, fim de contrato, aposentadoria ou "Outro" (aí aparece um campo para escrever).
- **Aviso de EPI em posse:** se o funcionário ainda está com EPIs, a tela mostra *"ainda tem N EPI(s) em posse; o ideal é registrar a devolução antes"*, com atalho para Troca / devolução.

**Se o funcionário está inativo:**

- aparece no topo a faixa **"Funcionário inativo · desligado em … · motivo: …"**;
- o botão **"+ Registrar entrega"** some;
- o botão **"Reativar funcionário"** faz ele voltar para a lista e poder receber EPI de novo.

### Local de estoque

No campo **Responsável** do cadastro de local, funcionário inativo não aparece mais para ser escolhido. A exceção é quando ele já é o responsável daquele local, para o cadastro não ficar quebrado.

## 3. O que mudou no banco (`18_funcionario_desligamento.sql`)

1. **Duas colunas novas:** `data_desligamento` e `motivo_desligamento`.
2. **Duas regras:**
   - só funcionário **inativo** pode ter data e motivo de desligamento;
   - a data do desligamento **não pode ser antes da admissão**.
3. **Um gatilho:**
   - se alguém inativar **sem informar a data**, o banco grava a data de hoje;
   - ao **reativar**, o banco **limpa** a data e o motivo.

**Por que o gatilho fica no banco e não só na tela?** Assim a regra vale para qualquer caminho: pela tela, pelo SQL Editor ou por uma importação futura.

**Quem pode inativar:** continua sendo só o Administrador, pela regra "funcionarios: administrador gerencia" da correção 09.

## 6. O que fica para depois

- **Devolução depois do desligamento.** A tela de Troca/devolução só lista funcionários ativos. Por isso a devolução deve ser feita **antes** de inativar. Uma melhoria futura é listar também os inativos que ainda têm EPI em posse. O banco já permite isso.
- **Importação por planilha:** uma matrícula que já existe como inativa é ignorada como "já cadastrada". Seria útil avisar que ela está inativa.

## 7. O que aprender com esta tarefa

- **Histórico não se apaga, se inativa.** O registro continua lá, mas sai do caminho do dia a dia.
- **Esconder não é proibir.** A lista esconde o inativo para facilitar o trabalho. Quem **proíbe** a entrega é o banco (correção 14).
- **Regra no banco vale para todos os caminhos.** A data automática e a limpeza ao reativar estão no gatilho, não só na tela.
