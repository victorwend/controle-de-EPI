# Relato — EPI-323: Cadastros só com tabelas de apoio

| | |
|---|---|
| **Tarefa** | EPI-323 (decisão do Victor em 31/10/2026) |
| **Branch** | `refactor/EPI-323-cadastros-apoio` |
| **Arquivos** | `frontend/src/pages/cadastros/CadastrosCentral.jsx`, `frontend/src/pages/epis/EpisLista.jsx` (botão da Matriz), `README.md` (Changelog) |

---

## 1. O problema

Havia **dois caminhos** para cadastrar funcionário:

| Caminho | Onde levava |
|---|---|
| Menu **Funcionários** | A **lista**, com os botões **+ Novo funcionário** e **Importar planilha** |
| Menu **Cadastros** → atalho **Funcionários** | Direto ao **formulário de novo funcionário** |

Os dois usavam a mesma tela de cadastro, então não era um cadastro duplicado. Mas quem entrava por **Cadastros** pulava a lista e **não via** o botão **Importar planilha** nem quem já estava cadastrado. Isso dava a sensação de conflito entre as duas telas.

O mesmo acontecia com **EPIs e CAs**, **Obras**, **Locais de estoque** e **Matriz EPI x Função**.

## 2. A decisão

**Cada cadastro tem um caminho só.** Na mesma conversa, o Victor ampliou a regra: *"da aba Cadastros pode tirar tudo aquilo que já tem aba no menu lateral, já que vai para o mesmo caminho"*.

| Atalho em Cadastros | Para onde foi | Situação |
|---|---|---|
| Funcionários | menu **Funcionários** | saiu |
| EPIs e CAs | menu **EPIs e CAs** | saiu |
| Obras | menu **Obras** | saiu |
| Locais de estoque | menu **Estoque** (botão "Novo local", que já existia) | saiu |
| Matriz EPI x Função | menu **EPIs e CAs** (**botão novo** "Matriz EPI x Função") | saiu |
| Fornecedores, Cargos/Funções, Setores, Categorias de EPI, Motivos de movimentação | não têm outro caminho | **ficou** |
| Usuários | o menu **Configurações** ainda é uma tela provisória | **ficou** |
| Cadastrar biometria | só aparece dentro dos fluxos de novo funcionário e de entrega | **ficou** |

## 3. O que foi mudado

Em `CadastrosCentral.jsx`:

1. Saíram 5 itens da lista `TILES` (tabela acima).
2. O texto da tela passou a explicar o que tem ali: *"Tabelas de apoio usadas pelo sistema. O que já tem menu próprio (Funcionários, EPIs e CAs, Obras e Estoque) é cadastrado por lá."*
3. Um comentário no código registra **por que** esses itens não estão ali, para ninguém "consertar" isso no futuro achando que foi esquecimento.

Antes de tirar os atalhos, conferi que as telas de lista continuam com o botão de novo, para nenhum cadastro ficar sem caminho:

| Menu | Botão de novo |
|---|---|
| Funcionários | `FuncionariosLista.jsx` → `/funcionarios/novo` ✅ |
| EPIs e CAs | `EpisLista.jsx` → `/epis-cas/novo` ✅ |
| Obras | `ObrasLista.jsx` → `/obras/nova` ✅ |
| Estoque (locais) | `EstoquePorLocal.jsx` → `/estoque/locais/novo` ✅ |
| EPIs e CAs (matriz) | **não tinha**. Criei o botão **Matriz EPI x Função** em `EpisLista.jsx` → `/epis-cas/matriz` ✅ |

A Matriz era o único caso em que tirar o atalho deixaria a tela **sem nenhum caminho**. Por isso ela ganhou um botão na lista de EPIs antes de sair de Cadastros. A própria tela da Matriz já se marca como parte do menu "EPIs e CAs".

As rotas (`/funcionarios/novo`, `/epis-cas/novo`, `/obras/nova`, `/estoque/locais/novo`, `/epis-cas/matriz`) **continuam existindo**. Só os atalhos em Cadastros saíram.

## 4. Atenção: diferença em relação ao Figma

A tela Cadastros foi feita a partir do protótipo **09.01** do Figma, que tem esses atalhos. Agora o sistema **é diferente do protótipo**. Para o Figma continuar sendo a referência da equipe, é preciso **tirar esses 5 blocos da tela 09.01** e incluir o botão da Matriz na tela de EPIs, ou pelo menos deixar uma nota nela com esta decisão. Isso está no card EPI-323 como pendência.

## 5. Como testar

1. `npm run dev` → menu **Cadastros**: aparecem só Fornecedores, Cargos/Funções, Setores, Usuários, Categorias de EPI, Motivos de movimentação e Cadastrar biometria.
2. Menu **Funcionários**: lista + **Importar planilha** + **+ Novo funcionário**.
3. Menu **EPIs e CAs**: botões **Matriz EPI x Função** e **+ Novo EPI**. Menu **Obras**: botão de nova obra. Menu **Estoque**: botão de novo local.

Conferi que o arquivo não tem erro de escrita. O `npm run build` roda no seu PC.

## 6. O que aprender com esta tarefa

- **Um caminho por tarefa.** Dois caminhos para a mesma coisa parecem ajudar, mas geram dúvida ("qual é o certo?") e telas que mostram coisas diferentes.
- **Antes de tirar um caminho, confira que o outro está completo.** Por isso a tabela da seção 3.
- **Documente o porquê no código** quando a escolha não for óbvia, principalmente quando ela contraria o protótipo.
- **O protótipo também precisa ser mantido.** Se o sistema muda, o Figma precisa acompanhar, senão a próxima pessoa segue o desenho antigo.
