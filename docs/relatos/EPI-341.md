## 1. Por que você precisava digitar a senha toda vez

O Supabase **já guardava a sessão** no navegador. O problema estava na tela inicial: o endereço `localhost:5173/` é a tela de login, e ela **sempre mostrava o formulário**, mesmo com você já conectado. Então parecia que tinha deslogado, mas era só a tela que não olhava a sessão.

## 2. Como ficou

1. **Já conectado? Vai direto para a Visão geral.** Abrir o sistema não pede mais a senha enquanto a sessão estiver válida. O Supabase renova a sessão sozinho.
2. **"Manter conectado neste computador"**, uma caixinha **marcada** por padrão:
   - **marcada:** a sessão fica guardada mesmo depois de fechar o navegador;
   - **desmarcada:** a sessão some quando você fecha o navegador. É o certo para **computador compartilhado**, como o da obra ou do almoxarifado.
3. **O e-mail já vem preenchido** no próximo acesso, quando "manter conectado" está marcado.
4. **"Esqueci minha senha" passou a funcionar.** Antes o botão não fazia nada. Agora:
   1. você digita o e-mail e clica no botão;
   2. o Supabase manda um e-mail com um link;
   3. o link abre a tela "Defina sua senha".
5. **"Salvar senha" do navegador:** os campos ganharam `name` e `autocomplete` certos. Assim o Chrome ou o Edge oferecem **"Salvar senha?"** e preenchem sozinhos da próxima vez.

## 3. Segurança: o que fica guardado e o que não fica

| Fica no navegador | Não fica |
|---|---|
| A **sessão** do Supabase, um "crachá" temporário que expira e é renovado | ❌ A **senha**: o sistema nunca guarda |
| A escolha "manter conectado" | |
| O e-mail, se "manter conectado" estiver marcado | |

Por que o sistema **não guarda a senha**? Qualquer código ou extensão que leia o navegador conseguiria pegá-la. Quem guarda senha de forma segura é o **gerenciador de senhas do navegador**, que é criptografado. Por isso o sistema só deixa os campos prontos para ele.

**Botão Sair** (EPI-334): apaga a sessão. No próximo acesso, a senha é pedida de novo, mas o e-mail continua preenchido.

## 4. Como foi feito

- **`lib/lembrarLogin.js`** cria o "armazenamento" que o Supabase usa para a sessão:
  - se "manter conectado" está marcado, usa o `localStorage`, que fica até apagar;
  - se não, usa o `sessionStorage`, que some ao fechar o navegador;
  - ao gravar num, limpa o outro, para não sobrar sessão esquecida.

  Se o navegador bloquear o armazenamento (por exemplo, no modo anônimo), o login continua funcionando, só sem lembrar.
- **`supabaseClient.js`** passa esse armazenamento para o Supabase, com renovação automática da sessão.
- **`Login.jsx`**: se já existe sessão, redireciona para a Visão geral. Também tem a caixinha, o e-mail lembrado e o "Esqueci minha senha".

## 6. Como testar

1. Entre com **"Manter conectado"** marcado. Feche o navegador e abra `localhost:5173` de novo: deve ir **direto para a Visão geral**.
2. Clique em **Sair**. A tela de login deve aparecer com o **e-mail já preenchido**.
3. Entre com a caixinha **desmarcada**. Feche o navegador inteiro e abra de novo: a senha deve ser pedida.
4. Clique em **Esqueci minha senha** com o seu e-mail e confira se o e-mail chega.

   ⚠️ Para o link funcionar, a URL `http://localhost:5173/definir-senha` precisa estar em **Authentication → URL Configuration → Redirect URLs** no Supabase. Ela já é usada pelo convite, então provavelmente já está lá.
