## 1. Como fica a tabela de caixinhas

A tabela de **Usuários e permissões** agora tem **dois grupos**:

**Abas do menu (o que aparece para o perfil)**

| Aba | Caixinha? | Padrão |
|---|---|---|
| Visão geral | ❌ Fixa: todos | Todos |
| Entregas de EPI | ✅ | Liberada para todos |
| Funcionários | ✅ | Liberada para todos |
| Estoque | ✅ | Liberada para todos |
| EPIs e CAs | ✅ | Liberada para todos |
| Obras | ✅ | Liberada para todos |
| Cadastros | ✅ | Liberada para todos |
| Relatórios | ✅ | Liberada para todos |
| Usuários e permissões e Configurações | ❌ Fixa: só o Administrador | Só o Administrador |

**O que o perfil pode fazer:** são as mesmas caixinhas da EPI-331 (EPIs, estoque, entregas, funcionários, obras, ver todas as obras).

**Por que o padrão é "tudo liberado"?** É o que já valia antes. Ao instalar, ninguém perde acesso de surpresa: você desmarca o que não quer.

**Visão geral é fixa** porque é a página que abre depois do login. Sem ela, a pessoa entraria numa tela vazia.

## 2. Ação e aba andam juntas

Não faz sentido alguém poder **entregar EPI** sem enxergar a aba **Entregas**. Por isso as duas andam juntas:

- **marcar uma ação marca a aba dela:**

  | Ação | Aba que é marcada junto |
  |---|---|
  | Entregar EPI | Entregas de EPI |
  | Estoque | Estoque |
  | EPIs | EPIs e CAs |
  | Funcionários | Funcionários |
  | Obras | Obras (e "Ver todas as obras") |

- **desmarcar a aba desmarca as ações dela.** Exemplo: tirar a aba Entregas tira "Entregar EPI".

O banco faz o mesmo ao salvar: se receber uma ação sem a aba dela, ele acrescenta a aba.

## 3. Onde a aba é escondida

1. **Menu lateral (`AppShell.jsx`):** aba não liberada **não aparece**.
2. **Endereço digitado à mão (`RequireAba.jsx`):** se alguém digitar `/estoque` sem ter a aba, a tela mostra *"Esta aba não está liberada para o seu perfil"*, com um link para a Visão geral. Vale para todas as telas de dentro da aba, como `/estoque/entrada` e `/estoque/locais`.
3. **Usuários e permissões e Configurações:** só abrem para o Administrador, tanto pelo menu quanto pelo endereço.

## 4. O que a aba controla e o que ela não controla

| | Quem garante |
|---|---|
| A aba **aparecer** no menu e a tela **abrir** | Frontend (esta tarefa) |
| **Gravar** (entregar, cadastrar, transferir…) | **Banco** (correções 19 e 20): recusa mesmo sem passar pela tela |
| **Quais dados** a pessoa lê | **Banco**: só os das obras liberadas (correção 16) |

**Por que a aba não bloqueia a leitura no banco?** As telas usam dados umas das outras. A Nova entrega, por exemplo, precisa ler funcionários e estoque. Se "sem aba Funcionários" bloqueasse a leitura de funcionários no banco, quem só pode entregar EPI não conseguiria escolher o funcionário. Então:

- a aba decide **o que aparece**;
- as obras liberadas decidem **quais dados**;
- as ações decidem **o que pode gravar**.

## 9. O que aprender com esta tarefa

- **Uma regra, vários lugares.** A mesma função, `abaDaRota`, decide o menu e a trava das rotas. Assim os dois nunca discordam.
- **Esconder ≠ proteger.** Esconder a aba organiza a tela. Quem protege os dados é o banco.
- **Padrão que não muda nada.** Instalar a correção não tira o acesso de ninguém. Quem decide restringir é o Administrador, pela tela.
