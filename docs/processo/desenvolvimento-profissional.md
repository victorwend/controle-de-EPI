# Processo de desenvolvimento profissional

## Cadência

- Sprints iniciais de duas semanas.
- Máximo de seis tarefas comprometidas para a dupla.
- Uma tarefa em andamento por pessoa.
- Reserva de aproximadamente 30% para estudo, revisão, correções e imprevistos.
- Capacidade recalibrada após duas sprints.

## Fluxo

`Backlog → Candidata → Comprometida → A fazer → Em andamento → Em revisão → Em teste → Concluído`

Tarefa bloqueada deve registrar causa, responsável e próximo passo.

## Cerimônias

- Refinamento: preparar tarefas futuras.
- Planejamento: definir objetivo, capacidade e compromisso.
- Daily: feito, próximo passo e impedimento.
- Review: demonstrar resultado funcionando.
- Retrospectiva: escolher uma melhoria concreta.

## Papéis

- Backend/Banco/Segurança.
- Frontend/UX/QA.
- Arquitetura, review, planejamento e integração são compartilhados.

## Rastreabilidade

`Necessidade → Requisito → Regra → Caso/User Story → Tarefa → Branch/PR → Teste → Versão`

## Ambientes

- Desenvolvimento: dados fictícios.
- Teste: banco descartável.
- Homologação: validação controlada.
- Produção: dados reais protegidos.
