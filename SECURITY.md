# Política de Segurança

## Versões suportadas

Enquanto o sistema não estiver em produção, apenas a versão presente nas branches ativas de desenvolvimento é considerada para correções.

## Como relatar uma vulnerabilidade

Não abra uma issue pública contendo detalhes de segurança, credenciais, tokens, dados pessoais ou biometria.

Use o recurso **Security Advisories** do GitHub para relatar o problema de forma privada ao responsável pelo repositório.

Informe:

- versão ou commit afetado;
- ambiente;
- passos seguros para reprodução;
- impacto;
- evidência sem dados reais;
- sugestão de mitigação, quando conhecida.

## Compromissos

- Segredos não ficam no repositório.
- Dados reais não são usados em desenvolvimento.
- Autorização é verificada no servidor.
- Operações de estoque são transacionais e auditáveis.
- Biometria não aparece em logs, relatórios comuns ou evidências.
- Dependências e vulnerabilidades são revisadas antes de cada lançamento.
